NOBA Archive Design Foundation

The minimum system the first real interface needs: tokens, bidirectional rules, and the accessibility floor. Not a style guide for a product that doesn't exist yet — the small set of decisions that would be expensive to reverse once a WinUI surface is built on top of them.

Position

Arabic is the design constraint, not a translation pass

7-Zip and WinRAR both render Arabic badly — mirrored layouts that leak, filenames that break at the wrong boundary, dialogs that assume a left edge. That is the gap this product is aimed at, which means right-to-left cannot be retrofitted after the English UI is finished. Every token below is declared in logical terms (inline-start, not left) so mirroring is a property of the system rather than a second stylesheet somebody has to maintain.

The engine already carries the matching half of this: a ZIP whose entry names are in a legacy code page is decoded, reported, and overridable, so an Arabic filename from a 2009 archive survives all the way to the screen. A design system that mirrors correctly and then shows ?????.txt would have solved the easier half of the problem.

Color

Surfaces, ink, accent, verdict

Neutrals are biased toward the accent's hue — a navy-grey, never a pure grey. Elevation in the dark theme comes from lighter surfaces, not shadows; shadows only appear in the light theme, where they read.

Accent & verdict

The accent is identity; the verdict colors are meaning. They never swap roles — a primary button is never green because the action is safe, and a blocked row is never blue because blue is the brand.

--blockedRefused by policy, integrity failure
--allowedPassed validation, verified
--cautionEncrypted, unverifiable, guessed
Type

One superfamily across both scripts

IBM Plex Sans and IBM Plex Sans Arabic are drawn as one family, so Latin and Arabic share weight, proportion and voice instead of being two typefaces stapled together. IBM Plex Mono carries paths, sizes, hashes and code pages — the data an archive manager is mostly made of.

Arabic needs more vertical room than Latin at the same size: line-height goes to 1.9 against Latin's 1.6, and ascender-heavy stacking makes tight leading illegible rather than merely tight.

Bidirectionality

What mirrors, and what must not

Mirroring everything is the common failure. Direction applies to reading order, not to things that carry their own intrinsic orientation or that are not language at all.

→← Mirrors

  • Layout order, alignment, indentation
  • Navigation and tree disclosure arrows
  • Back / forward, breadcrumb separators
  • Icons that imply direction of travel
  • Table column order
  • Padding, margin, border via logical properties

✕ Never mirrors

  • File paths — C:\Users\m\Desktop is not prose
  • Progress fill — grows with time, not with script
  • Checkmarks, warning triangles, padlocks
  • Version strings, CRC and hex values
  • Media transport controls
  • Company logos and product marks

Paths inside Arabic prose

A Windows path dropped into an Arabic sentence will reorder itself into nonsense unless it is isolated. Every path, identifier and numeric literal gets direction: ltr; unicode-bidi: isolate — in WinUI, the equivalent is an explicit FlowDirection.LeftToRight on the run, not on the panel.

تم رفض المدخل ..\..\Windows\System32\evil.exe لأنه يحاول الخروج من مجلد الوجهة.

Progress does not flip

A 62% extraction is 62% done in both directions. The bar fills from the same physical edge because it represents elapsed work, not a sentence — and a user watching it flip direction when they change language will read it as a bug.

Numerals

Arabic-script locales split on digit shape, and guessing wrong looks careless in both directions. NOBA Archive uses Western digits (0–9) everywhere by default, including Arabic UI, because sizes, checksums and version numbers are read alongside data the system produces. Arabic-Indic digits (٠–٩) are a per-user setting, and never apply to --name-encoding 1256, CRC values, or anything copyable.

Accessibility

The floor, not the aspiration

RuleRequirement
Text contrast4.5:1 body, 3:1 for text at 24px+ or 19px bold — in both themes, checked against the surface actually behind it.
Never colour aloneBlocked and allowed carry an icon and a word. A red row and a green row are identical to roughly 1 in 12 men.
Focus2px --accent ring, 2px offset, visible on every focusable control. Never removed for aesthetics.
Target size24×24 CSS px minimum for any pointer target, including row-level icon buttons.
Motionprefers-reduced-motion disables transitions and progress animation; the progress number keeps updating.
KeyboardThe whole extract flow — select, choose destination, review refusals, confirm — completes without a pointer.
Screen readersA refused entry announces the reason, not just "blocked". The reason is the security value.
